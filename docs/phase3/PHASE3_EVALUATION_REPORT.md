# Phase 3 Evaluation Report — VoiceMirror

Method: [PHASE3_EVALUATION_PLAN](PHASE3_EVALUATION_PLAN.md). All numbers below are generated by `eval/voicemirror/summarize.py` from the committed result files:
* **Run 1** `eval/voicemirror/results/run1_tempo_enabled.json` (+ `.summary.md`): the prototype with tempo transfer on.
* **Run 2** `eval/voicemirror/results/run2_shipped.json` (+ `.summary.md`): **the shipped configuration** (tempo transfer disabled because of run 1).

Environment: 4 vCPU, no GPU, Node 22.23.5, espeak-ng 1.51, Resemblyzer 0.1.4, librosa 1.0.1, pocketsphinx 5.1.1. Each run took ~30 min. **All voices are synthetic.** Results rank approaches and verify engineering behaviour; they don't predict how real people will perceive the voices.

## 1. Headline (run 2, shipped)

18 synthetic speakers × 30 ordered language pairs (en, es, de, hi, ja, ru) = 540 outputs per condition. Descriptor coverage 100%. Cosine between *different* speakers (reference level): **0.765**.

| Condition | Cosine mean | Top-1 identification | Mean rank (of 18) | Pitch error median (st) | Pitch error p90 | Tempo error median | Tempo error p90 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `baseline` (today) | 0.741 | 5.6% | 9.5 | 6.70 | 17.12 | 14.6% | 25.0% |
| **`vm_prosody`** (browser path) | **0.800** | **13.7%** | **6.5** | **1.10** | 8.40 | 14.6% | 25.0% |
| **`vm_register`** (server path) | 0.775 | 6.1% | 7.8 | 5.00 | 10.10 | 14.6% | 25.0% |
| `oracle_prosody` (ceiling of this approach) | 0.800 | 15.2% | 6.4 | 0.60 | 8.41 | 0 | 0 |
| `oracle_select` (ceiling of stock-voice selection) | 0.826 | 2.8% | 4.6 | 0.40 | 1.00 | 0 | 0 |
| `oracle_full` (ceiling of perfect cloning) | 0.898 | 85.7% | 1.2 | 0.50 | 1.10 | 0 | 0 |

### What this shows, separately per dimension
1. **Selected characteristic: pitch is preserved.** Median output-pitch error drops from 6.70 to **1.10 semitones**. It improves in **all 30** language pairs (by 4.15–6.65 st per pair) and is consistent across target languages (0.93–1.16 st). This is the claim the prototype makes, and it holds on this data.
2. **The prototype reaches its approach's ceiling.** `vm_prosody` (0.800, rank 6.5) matches `oracle_prosody` (0.800, rank 6.4), so the analyzer/descriptor chain loses almost nothing compared with knowing the true pitch.
3. **Identity is not preserved, and the approach can't preserve it.** Cosine rises 0.741 → 0.800, only just above the different-speaker level (0.765). Top-1 identification is 13.7%, against 85.7% for perfect cloning. Every pair improves (Δcos +0.044 to +0.085), but the gap to `oracle_full` is ~2× the gain. **VoiceMirror must not be described as preserving voice identity.**
4. **The server path (`vm_register`) is weak:** pitch error 5.00 st, cosine +0.034 (28 of 30 pairs improve). Choosing a stock voice by register without pitch control is coarse.
5. **Stock-voice selection is a different trade-off:** the best possible selection (0.826) sounds more similar while almost never being mistakable for the speaker (2.8%). That's resemblance without impersonation, the expected profile of tier C in the research decision.

### Pitch tail: a render-voice limit, not an analyzer error
p90 pitch error is ~8.4 st for **both** `vm_prosody` and `oracle_prosody`. Per speaker, the error is large only for high-pitched speakers. The default render voice (espeak m1) can produce only **58–154 Hz** (calibrated), so higher targets clamp at the engine's maximum. Example: speaker f5/p75, `vm_prosody` 9.05 st vs `oracle_prosody` 9.10 st. Where the render voice can reach the target, the error is ~0.4–1.1 st. **Product implication:** pitch transfer needs a render voice whose range covers the speaker, i.e. register-based voice choice *combined with* pitch control. The browser path (pitch multiplier on a system voice) and the provider path (no pitch control) each have only half of that.

## 2. Tempo: run 1 finding and decision

| | Run 1 (tempo transfer on) | Run 2 (shipped: off) |
| --- | --- | --- |
| `vm_prosody` tempo error median / p90 | 15.0% / **37.5%** | 14.6% / 25.0% (= baseline) |
| by true speaker speed 140 / 175 / 205 wpm | 31.2% / 20.0% / 6.7% | 25.0% / 0.0% / 14.6% |
| Baseline (no transfer) | 14.6% / 25.0% | 14.6% / 25.0% |

The tempo estimate tracks speed well on the calibration speakers (rank correlation 0.879, English). Across other timbres and languages it was **no better than not transferring tempo, and worse in the tail**. It was badly off for slow speakers. The evaluation plan's stated rule applied: **tempo transfer is disabled** (`TEMPO_TRANSFER_ENABLED = false`). The descriptor always carries a neutral tempo, so the characteristic isn't transmitted. The browser E2E had shown the same problem before the full run (a 150 wpm voice produced a 1.20 tempo hint).

## 3. Analyzer accuracy
* **Exact synthetic tones** (80–350 Hz, 16 and 48 kHz, ±0.5 st vibrato): median absolute pitch error **0.069 st**, max 0.142 st (n=12).
* **Unit tests:** within 0.5 st at 80/120/180/240/320 Hz at both sample rates; syllable-rate estimate monotonic in pulse rate.
* **In a real browser capture** (Chromium fake mic playing a synthetic ~81 Hz voice through `getUserMedia` with echo cancellation/NS/AGC): the analyzer measured 82.4 Hz (processed) and 83.6 Hz (raw).

The analyzer accumulates evidence across turns. The first descriptor needs ~1 s of voiced speech (a single sentence gives median 1.25 s voiced). The browser E2E confirmed this: the first 3 s turn was withheld, and the descriptor arrived after the next turn.

## 5. Intelligibility proxy (English targets only; relative)

pocketsphinx WER (lower is better). Absolute WER is high for all conditions because the recognizer handles espeak speech poorly.

| Condition | WER mean (n=80) |
| --- | --- |
| baseline | 0.66 |
| vm_prosody | 0.75 |
| vm_register | **0.90** |
| oracle_prosody | 0.77 |
| oracle_select | 0.76 |
| oracle_full (the speaker's own voice) | 0.76 |

| Default voice at parameter extremes | WER mean |
| --- | --- |
| neutral | 0.73 |
| lowest pitch the descriptor can produce | 0.68 |
| highest pitch the descriptor can produce | 0.80 |
| tempo 0.80 / 1.25 (no longer produced) | 0.70 / 0.84 |

**Interpretation, with its limits:** every voice other than the recognizer's best-matching default scores worse, *including the speakers' own voices*. So the proxy can't separate a real intelligibility cost from recognizer bias. `vm_prosody` is in line with the oracles; **`vm_register` is the worst** and is a risk to check. High pitch settings also score worse. Intelligibility **must be checked with human listeners** before VoiceMirror is used in production; this proxy neither passes nor fails it.

## 6. Naturalness / prosody
Not measured as perceived quality: no human MOS was possible, and espeak is not natural speech. What is ensured by construction and tests: render parameters are always inside clamps (exhaustive test), and hints change only between segments, never inside one. **Naturalness is unevaluated.**

## 7. Cross-language consistency
Evaluated: all 30 ordered pairs among en, es, de, hi, ja, ru. Pitch improvement and cosine gain are positive in every pair. Per-target pitch error ranges 0.93–1.16 st (`vm_prosody`).
**Not evaluated:** the other 25 Talktual languages. The analyzer is language-independent (pitch), but nothing here verifies them.

## 9. Limitations
* Synthetic voices only (espeak formant synthesis); human voices are more varied, and identity cues the encoder relies on may differ.
* The GE2E encoder is a proxy for perceived similarity and "works best on English" (its README).
* Intelligibility proxy is English-only and biased toward the default voice; naturalness is unmeasured.
* Provider TTS output (ElevenLabs voices and speed) wasn't evaluated: no paid calls.
* Single run per configuration (deterministic synthesis and seeds; results are reproducible rather than sampled).
